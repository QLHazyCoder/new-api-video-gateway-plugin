# 客户端生图与视频生成 Skill 使用教程

本文面向希望直接在 AI 客户端里生图、编辑图片或生成视频的普通用户。安装 **Coder Media Generation** 后，可以用自然语言选择分组、模型和参数，由客户端执行生成、查询与下载流程，无需自己编写 API 请求。

Skill 名称是 **`coder-media-generation`**，仓库地址为 [Coder Media Generation Skill](https://github.com/QLHazyCoder/coder-media-generation-skill)。它与 New API 管理员安装的任务插件是不同的东西：普通用户只需在自己的客户端安装本 Skill，不需要部署 New API。

## 1. 准备工作

你需要：

- 能加载 Agent Skills 并执行本地 Python 脚本的 AI 客户端。本文提供 Codex 和 Claude Code 的安装与调用方式。
- 实际执行脚本的环境里有 **Python 3.11 或以上版本**。下面的终端命令以 macOS、Linux 为例；Windows 用户可在 WSL 中按 Linux 方式操作，并让客户端也在对应 WSL 环境执行。
- 本服务签发的 API Key，以及它所属的分组和模型权限。仅有客户端登录账号不等于已有媒体生成密钥。
- 执行环境可以访问本服务和公开模型目录；安装时还需要能下载 GitHub 仓库。生成会消耗本服务账户额度。

如果客户端连接的是远程开发机或容器，Skill、Python、密钥和输出文件都位于实际执行环境，不一定在你眼前这台电脑。先明确执行位置，再安装。

只支持填入“API 地址和模型名”的普通聊天客户端，不会因此自动获得执行这个 Skill 的能力。

## 2. 安装 Skill

### Codex：让内置安装器完成安装

在 Codex 中发送下面这段话即可：

```text
$skill-installer
请从 https://github.com/QLHazyCoder/coder-media-generation-skill 安装 Skill。
Skill 位于仓库根目录，安装名称使用 coder-media-generation。
仅安装并检查 Python 运行环境，暂时不要生成图片或视频，不要改动其他 Skill。
如果已经安装，先检查现有目录，不要重复创建同名副本或覆盖我自己的修改。
```

安装完成后，让 Codex 确认可以读取该 Skill 的 `SKILL.md` 和 `scripts` 目录。没有立即识别时，可以重新打开客户端或新建会话，再明确调用 `$coder-media-generation`。

### Codex：手动安装

当前官方文档使用 `~/.agents/skills` 作为个人 Skill 目录，也支持项目下的 `.agents/skills`。参见 [OpenAI 官方 Skill 文档](https://developers.openai.com/codex/skills#where-to-save-skills)。

如果确定尚未安装，可以在终端执行：

```sh
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/QLHazyCoder/coder-media-generation-skill.git \
  "$HOME/.agents/skills/coder-media-generation"
```

如果你的客户端已有其他 Skill 安装目录，例如已有的 `~/.codex/skills`，优先沿用客户端实际识别的目录，不要同时在两个位置重复安装同名 Skill。使用内置安装器时，以其返回的实际安装路径为准。

### Claude Code：安装到个人 Skill 目录

Claude Code 的个人 Skill 目录是 `~/.claude/skills`，可通过 `/技能名` 调用。参见 [Claude Code 官方 Skill 文档](https://code.claude.com/docs/en/skills)。

确认尚未安装后，在终端执行：

```sh
mkdir -p "$HOME/.claude/skills"
git clone https://github.com/QLHazyCoder/coder-media-generation-skill.git \
  "$HOME/.claude/skills/coder-media-generation"
```

之后在 Claude Code 中输入 `/coder-media-generation`。本仓库提供的是 Skill 文件和 Python 脚本，客户端仍需要有实际执行脚本、访问服务和保存文件的权限；不要把仓库地址填写成聊天模型的 API 地址。

### 没有 Git 时

直接 [下载 Skill 完整压缩包](https://github.com/QLHazyCoder/coder-media-generation-skill/archive/refs/heads/main.zip)，解压后把包含 `SKILL.md` 的目录改名为 `coder-media-generation`，放进对应客户端的 Skill 目录。

目录结构应当是：

```text
客户端的 skills 目录/
└── coder-media-generation/
    ├── SKILL.md
    ├── scripts/
    │   ├── generate_image.py
    │   ├── generate_video.py
    │   └── media_catalog.py
    ├── references/
    └── agents/
```

不要只复制 `SKILL.md`，也不要多套一层同名文件夹。生成需要调用附带的脚本。

## 3. 第一次使用：先查看分组与模型

安装后，先发送下面的请求。Codex 用户保留 `$coder-media-generation`；Claude Code 用户把第一行换成 `/coder-media-generation`：

```text
$coder-media-generation
先不要生成，帮我检查 Python 环境，并列出当前可用的生图模型、视频分组和各组的视频模型。
同时告诉我各模型需要哪些参数、有哪些分辨率和时长可以选择。
```

Skill 会读取公开模型目录，再结合已验证的模型参数表展示选项。当前已整理的五个视频分组如下，之后以客户端读取到的实时目录为准：

| 视频分组 | 密钥如何配置 |
| --- | --- |
| `视频模型` | 单独保存该分组的密钥 |
| `seedance官渠 720&1080p 国内` | 单独保存该分组的密钥 |
| `视频-seedance官渠-全分辨率-国内` | 单独保存该分组的密钥 |
| `seedance官渠 全分辨率 海外版` | 单独保存该分组的密钥 |
| `seedance官渠 720p 海外版` | 单独保存该分组的密钥 |

当前目录中，`视频模型` 包含 Grok、H3、Seedance、Wan 等 13 个已支持的视频模型；其余四组各有四个 `doubao-seedance-*` 模型。`wan3.0-official` 支持 480p/720p/1080p、2–30 秒和 `-1` 自动时长。分组名和模型名是不同选项，不能用模型名代替分组名。

**公开目录中看得到，不代表你的密钥一定有权限；插件或 Skill 认识的分辨率，也不代表每个服务分组都提供。** 例如选择仅提供 720p 的分组时，应使用 720p，而不是按另一个分组的范围选择 1080p。

如果目录新增模型，但 Skill 显示“未配置”或“参数尚未验证”，暂时不要让客户端猜参数生成；需要先更新到已验证支持该模型的 Skill 版本。

## 4. 密钥按分组保存，不需要一次准备齐

规则是：**每个视频分组保存一把对应密钥，生图密钥另外保存。** 以后增加分组还可以继续补充。你只使用其中一组时，只需配置那一组，不要求提前保存全部密钥。

| 你要做的事 | 使用哪把密钥 |
| --- | --- |
| 生图、编辑图片 | 单独保存的生图密钥 |
| 在某个视频分组中生成、查询和下载视频 | 该视频分组对应的密钥 |
| 为本次图生视频上传本地图片 | 复用本次选中的视频分组密钥，不再要求一把图床密钥 |

你选择分组后，Skill 会查找该组密钥；没有就会明确告诉你缺少哪一组的密钥，并在上传或生成前停住，不会改用其他组或生图密钥。

首次配置时，告诉客户端密钥对应的用途和**完整分组名**，例如：

```text
我要使用“seedance官渠 720p 海外版”分组。
如果本机没有保存该组密钥，请先引导我配置，只保存到这一组，不要改动其他分组或生图密钥。
生成配置确认前不要提交任务。
```

密钥应通过客户端提供的本地隐藏输入方式交给脚本；不要把真实密钥写进示例提示词、共享文档或项目文件。脚本将密钥保存到执行环境的用户私有配置目录，不放在 Skill 仓库中，也不写入视频任务状态。

新安装通常保存到 `~/.config/coder-media-generation/credentials.json`；已有旧版 `coder-api-image` 配置时会兼容使用旧位置。不要把整个凭据文件贴出来排查。配置好后再次使用同一分组，无需重复提供密钥。

同一分组更换密钥时，只更新这一组。是否有余额、是否授权具体模型，以及 IP 限制等，仍以服务侧设置和实际请求结果为准；本地保存成功不是在线认证成功。

## 5. 日常使用时会问什么

你可以先给简单需求，Skill 再把所需选择集中问清楚；也可以一次提供完整设置：

| 类型 | 需要明确的内容 |
| --- | --- |
| 生图 | 提示词、模型、尺寸或分辨率与比例、是否优化提示词 |
| 图片编辑 | 编辑要求、本地参考图片、支持编辑的模型、输出尺寸、是否优化提示词 |
| 视频 | 视频分组、模型、提示词、时长、分辨率；按模型补充比例、素材及其他需要的参数；是否优化提示词 |

模型支持哪些值，由 Skill 的模型表和服务分组能力共同决定。不需要的参数不必填写，已经说清楚的参数也不用重新回答。

如果你要求优化提示词，客户端会先给几个不同版本，让你选定或修改，然后才使用确认后的提示词。无需优化时直接说“使用原提示词，不优化”。

## 6. 生图与图片编辑示例

### 生图：一次给出完整设置

```text
$coder-media-generation
帮我生成一张咖啡馆海报，暖色调，桌上放一杯拿铁，留出顶部标题区域。
模型选择 gpt-image-2，尺寸 1024x1536。
不优化提示词，使用本机保存的生图密钥，生成一张后保存到当前项目的 outputs 目录。
```

GPT Image 模型使用像素尺寸；Gemini 和 Grok 生图模型使用比例加分辨率。换模型时不要照抄不适用的尺寸参数，可以先让 Skill 展示该模型选项。

### 先优化提示词，再生成

```text
$coder-media-generation
我想做一张雨夜城市壁纸，先不要生成。
请先列出适合的生图模型和参数选项，再给我三个提示词优化版本。
我确认模型、尺寸和提示词版本后再生成。
```

### 编辑一张现有图片

先把图片作为客户端附件提供，或指定执行环境能够读取的本地图片路径：

```text
$coder-media-generation
请把附件里的产品图背景改成白色摄影棚，保持产品外观不变。
使用 gpt-image-2 编辑，输出尺寸 1024x1024，不优化提示词。
保存到当前项目的 outputs 目录。
```

当前 Skill 的图片编辑只支持 `gpt-image-2`，本地输入支持 PNG、JPEG、WebP，最大 50 MiB。不要默认其他生图模型也支持图片编辑。

## 7. 文生视频示例

```text
$coder-media-generation
我要生成一个视频：透明玻璃瓶放在木桌上，阳光穿过玻璃，镜头缓慢推进。
视频分组选择“seedance官渠 720p 海外版”。
模型选择 doubao-seedance-2-0-mini-260615。
时长 4 秒，分辨率 720p，比例 16:9，不优化提示词。
使用这个分组已保存的密钥；如果没有，先让我配置。
只生成一次，完成后下载到当前项目的 outputs 目录。
```

这是一份生成请求示例，只有当你的密钥已授权该模型且允许这些设置时才能使用。提交前客户端还会按该模型校验；如果报参数或权限错误，应修正原因，不要让它盲目更换分组、降低分辨率或反复重试。

## 8. 图生视频与多素材参考

### 使用本地图片

```text
$coder-media-generation
用附件这张产品图生成视频，保持产品外观不变，镜头从左向右缓慢移动。
分组选择“视频模型”，模型选择 grok-imagine-video-1.5。
时长 5 秒，分辨率 720p，不优化提示词。
使用该分组密钥，完成后保存视频。
```

当前两个 Grok 视频模型支持把本地图片直接发送给视频接口；其他当前支持的模型需要公开图片 URL。对这些需要 URL 的模型，Skill 会先用本次视频分组密钥上传本地图片，再把返回的图片地址用于生成，不需要另外配置图床密钥。

如果你不希望上传图片，应先明确告诉客户端不要上传；可以自行提供已经公开可访问的图片 URL。图生视频输入图片最大 20 MiB，支持 PNG、JPEG、WebP。

### 使用公开图片、参考视频或音频

```text
$coder-media-generation
我想结合一张产品图和一个动作参考视频生成视频，先不要提交。
分组选择“seedance官渠 全分辨率 海外版”，模型选择 doubao-seedance-2-5-260628。
产品图：https://media.example.com/product.jpg
动作视频：https://media.example.com/motion.mp4
希望输出 8 秒、720p、16:9，请先检查素材类型和参数是否支持，再询问我是否需要优化提示词。
```

示例地址必须替换成真实素材。参考视频和参考音频在当前 Skill 中需要公开 URL，不会自动把本地视频、音频上传到图床。图片、视频和音频的数量及组合都要遵守模型限制；H3 不支持参考视频，两个 Grok 模型也不接受多图或视频/音频参考。

## 9. 结果保存、任务恢复与费用

图片生成后，客户端会返回实际使用的模型和本地文件路径。视频生成会先获得任务 ID，再轮询同一个任务，成功后下载 MP4，并返回分组、模型、任务 ID 和文件位置。

如果客户端在远程主机或容器里执行，返回的也是那里的路径；本地客户端能预览时可以直接查看，否则需要从实际执行环境取回文件。

视频生成中的客户端断线或查询失败不代表任务没有创建。可以这样要求恢复：

```text
继续刚才的视频任务。请使用原分组和已保存的任务状态查询并下载，
不要重新创建任务；如果提交结果不确定，先查找原任务 ID，再向我说明情况。
```

视频提交结果不确定时，Skill 不会自动再提交；已有任务的状态查询和下载可以继续。图片生成的部分暂时性错误会有限重试，具体以客户端提示为准。生成费用由服务模型、参数、分组和实际用量决定，提示词优化使用的聊天模型也可能由客户端另行计费。

## 10. 更新与卸载

更新的是客户端实际安装的 Skill 目录，不是某个另外克隆的副本。可以直接告诉客户端：

```text
请检查当前实际安装的 coder-media-generation，
从 https://github.com/QLHazyCoder/coder-media-generation-skill 更新。
保留我的生图密钥、所有视频分组密钥、已有任务状态和生成结果；
如果目录有我自己的修改，先说明差异，不要覆盖。
这次只更新 Skill，不创建图片或视频任务。
```

若是手动通过 Git 安装，先在实际 Skill 目录运行 `git status --short` 检查有无自己的修改，确认干净后再执行 `git pull --ff-only`。用压缩包安装时，更新前备份现有目录，只替换 Skill 文件，不覆盖私有凭据和输出目录。

卸载时移除客户端实际安装的 `coder-media-generation` 目录。私有凭据、任务状态和输出文件位于其他位置，不会因为卸载 Skill 自动全部删除；如需清理，明确告诉客户端要清理哪一组密钥、哪些任务或输出，避免误删其他组配置。

## 11. 常见问题

| 现象 | 如何处理 |
| --- | --- |
| 客户端找不到 Skill | 检查安装目录、`SKILL.md` 是否位于正确层级，重开会话并明确调用对应客户端的 Skill 名称 |
| 提示找不到 Python 或语法不支持 | 在实际执行环境安装或选择 Python 3.11 以上解释器，不是只在另一台主机安装 |
| 明明保存过密钥，仍提示缺钥 | 核对是否同一个执行环境、同一个完整分组名；生图密钥和其他视频组密钥不能代替当前组 |
| 本地保存成功，但调用 401 / 403 | 核对该组密钥是否有效、有模型权限，以及服务侧额度或 IP 等限制 |
| 分组或模型出现在公开目录但不能调用 | 核对密钥授权和服务可用性；未验证的模型需要先更新能力配置，不能只看目录可见性 |
| 分辨率或时长被拒绝 | 同时检查模型范围和该服务分组限制，不从其他模型或分组套用参数 |
| 本地图片上传失败 | 检查执行环境是否能访问图片上传地址、密钥是否有效、图片格式和大小；失败后不会继续提交视频 |
| 提供本地视频或音频无法作为参考 | 当前需要先自行取得公开可读 URL，Skill 没有承诺本地视频/音频托管功能 |
| 视频生成很慢或客户端断线 | 保留原任务 ID 和状态继续查询，不重复创建 |
| 显示已完成，但下载失败 | 继续下载原任务，不要重新生成；也检查输出目录权限和网络 |
| 生成结果在另一台机器 | 检查客户端的实际执行位置，从那台主机或容器取回文件 |

安装后最简单的起点是：“使用这个 Skill，先列出我可以选择的分组和模型，先不要生成。”确认分组、模型、参数和密钥后，再开始第一次生成。
